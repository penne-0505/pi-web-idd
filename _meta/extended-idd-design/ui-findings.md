## 既存 pi-web への統合形態

- sidebar 上部に `Sessions ⇄ Lanes` の mode 切替を足す。既存の session 一覧は無変更
- TabBar に `Inbox` を常設 (閉じられない)。badge = 判断待ち件数
- lane 行を押すと main に lane タブが開く (file タブと同じ機構)。chat は lane タブ内の agent 導線から開く
- 既存 UI への改変はこの 3 点のみ

## sidebar の構成

```
Pi Web
Sessions | Lanes 7
─────────────────
all areas ▾
─────────────────
判断待ち 4        ← 判断の種類ごとにアイコン
下調べ中 1 / 5     ← planner の並列上限
実装中 2 / 3       ← executor の並列上限
待機中 1           ← 鎖アイコン付き = 依存待ち / 無し = 空き待ち
終端 (直近) ▾
─────────────────
今すぐ取り込む
```

- **worker capacity を独立表示しない。** section 見出しの `n / 上限` がそれを兼ねる。満杯なら直下の「待機中」が結果を示す
- lane 行は 2 段。1 段目 = title (+ 判断の種類アイコンを右端に)、2 段目 = stage bar + 経過
- **内部 ID と外部参照は行から外す** (実装で改訂)。詳細画面に必ずあり、一覧では選ぶ材料にならない
- **1 行の視線の入口は title 1 つ**。群ごとに title の重みを単調に落とす (判断待ち 600 → 実装中 500 → 待機中 muted → 終端 dim)、従の行は濃度を 100 / 75 / 50% に
- 判断を待っている行だけ左端に 3px の縦線。群を跨いで一目で拾える

## 判断 card (Inbox) の確定形

| card | 主 | 対になる操作 | 入力 |
| --- | --- | --- | --- |
| 重複確認 | — (対等な二択) | まとめる / 分ける (segmented) | — |
| 質問 | 回答して再開させる | — | 選択肢 + 理由 |
| GO 待ち | GO | 中止 | — |
| 差分確認 | 承認 | 実装へ戻す / 方針へ戻す | 指示 |
| 提出前確認 | このまま出す | 直させる / 切り出す | 指示 |

共通規約:

- **中身が毎回変わるもの (agent 生成の選択肢) はリスト、固定ラベルの操作はアイコン付きボタン**
- **無操作と結果が同じ操作はボタンにしない。** 持ち越しが既定なので「後で」「保留」は置かない (lifecycle event が別に立つ `s1_defer` / `s3_defer` のみボタンに値する)
- **押したら確定。** 二段階が要る操作は入力欄を先に置き、ボタンは常に確定にする
- 操作の並びは `主ボタン | 仕切り | 対になる操作 (縦積み) | 入力欄`。mobile では縦積み
- 選択状態は枠の濃度のみで示す (0.84 → 0.6)。太字への切り替えは字幅が変わるので使わない
- 判断 card から agent に聞き返す導線 (吹き出し) を持つ。**聞き返しは lifecycle event を発火しない**。決定はボタン、agent は助言のみ書き戻す

## 主題の構造 = 表示の構造

- 重複確認は 1 件の起票ではなく **2 件の関係**が主題 → 上下 2 枚 + 合流の記号。**語ではなく形で状態を示す** (実装で改訂):
  - 来たもの = **破線の枠** (まだ lane として実体がない) / 既存 = **実線 + 地 + stage bar** (実在して進んでいる)
  - `新規` / `既存` のラベルは置かない。ラベルは読まないと分からない
  - 題名の**共通部分に下線**を引き、重なりの照合を UI 側で済ませる (2 文字以上の最長一致を貪欲に取る)
  - 類似度 bar は 2 枚の間 (関係を表す部分) に置く。どちらか一方の属性ではないため
- 差分確認も同様 → `対象 / 衝突相手` の 2 行対比 + 2 pane の diff
- 提出前確認は 1 つの成果物の姿が主題 → 単一面のプレビュー + 指摘をその行に刺す (2 pane にしない)
- diff の既定展開は **衝突があるときだけ**。無いときは条件の確認で足りる

## lane detail の primitive

1. **契約** — やること (DEC) と 満たすべき条件 (QA、状態付き)。進捗を別に持たない (進捗 = 契約のどこまで満たしたか)
2. **現物** — 触っているファイルと、executor stream の tail。turn 境界で話しかける入力欄を stream に付ける
3. **経過** — 縦の rail。marker の形で agent の動き / 自分の判断 / 失敗を分ける

GO 待ちのときは 1 に INV を足し、2 を「下調べで見たもの (参照 + なぜ見たか)」に差し替え、末尾に GO / 中止。

## mobile (390)

- 2 pane の diff → 1 列の unified diff
- 横並びの操作列 → 縦積み (主ボタン全幅 → 対 2 つを半分ずつ → 入力欄)
- sidebar → overlay drawer (320px)
- tap 対象は最小 44px。lane 行は 58px。押せるものが隣接する箇所ほど間隔を広げる

## 設計側への要求

`open-questions.md` の 13-18 を参照。特に:

- planner の出力に書式と長さの制約が要る (選択肢 label 40 文字以内、DEC/QA の見出しが parse 可能な形)
- 選択肢の `description` は UI に出さないが schema には残す (envelope の echo と agent の判断材料)
- Verifier 態度 3 の回答を記録する event が無い

# 実装フェーズで確定したもの (2026-08-27)

wireframe から実装へ移す過程で、wireframe に無かった規約が固まった。以降はこちらが優先。

## 判断キューは一覧ではなく札束 (1 画面 = 1 判断)

lane / project をまたぐ context switch の頻度を下げるため、Inbox は card を縦に並べず**重ねる**。

- 前面の 1 枚だけが判断可能。背後は最大 2 枚ぶんの厚みとして見える (終端では厚みが消える)
- 左に**残りの札の列** — 判断の種類アイコンのみ。前面から離れるほど指数減衰で小さく薄くなる (`17 + 17 × 0.55^d`)。「あと何枚か」ではなく「近いか遠いか」だけが読めればよい
- めくる操作は ↑↓←→ キー / 器の右の 1 対のボタン / **card の外でのホイール** (閾値 90、1 弾みで 1 枚)
- 軸は縦に統一。次は下で待ち、判断済みは手前へ抜ける

## card は器を先に決め、中身を器に合わせる

card の高さを中身で決めると、めくるたびに枠も操作も動く。器の高さを外から固定した (`clamp(400px, 60vh, 700px)`)。

card は 3 面構造:

| 面 | 中身 | 動き |
| --- | --- | --- |
| 上 (固定) | 識別 + **主題** | 動かない |
| 中 (流れる) | 根拠・現物・操作対象 (下調べ、差分、条件、選択肢) | ここだけスクロール |
| 下 (固定 = HUD) | 操作 | 動かない |

- **主題は識別に属する。** 質問 card の質問文は情報ブロックではなく識別側に置く (選択肢を選ぶ間も消えない)
- 上下の境界には**消え際 (grad)** を置く。線ではなく消え方で続きを示す
- **自前の枠を持つブロック (差分 / PR プレビュー) は自分の器を持つ** (220px + 内側スクロール)。card のスクロールで行の途中から切られると、枠の下辺が消えて次のブロックに貼り付いて見える
- 情報ブロックを入れ子のスクロールにしてはいけない。兄弟が高いとき flex で 0 まで潰れ、中身へ到達できなくなる
- mobile は器を持たない (操作が縦に積まれて器を食い尽くすため、中身なりの高さで素直に流す)

## 判断を押したあとの状態

楽観更新しない (記録できるまで queue から消さない) 以上、UI に 3 状態が要る。

| 状態 | 見え方 |
| --- | --- |
| 記録中 | 札が沈み操作を受けない + 上辺を線が 1 本走る |
| 記録できた | 札が**手前へ抜ける** (1.03 拡大 + 淡く、180ms) → 次の札が下から入る |
| 記録できなかった | 札は queue に残り、**操作面のすぐ上**に短く揺れて申告 |

失敗は画面上部の帯ではなく card の中に出す。押した場所と結果が離れていると繋がらない。

## motion の原則

1. 動きは**状態変化の説明にだけ**使う。装飾の動きは置かない
2. **位置が変わらないものは動かさない** (器 / HUD / 識別)。動くのは中身と札だけ
3. 動く**向きは意味の向き**と一致させる
4. 速さは 3 段 — 押下 90ms / 入れ替え 160ms / 面の転換 240ms。曲線は 1 種類 (`cubic-bezier(.2,0,0,1)`)
5. 同時に動くものは 1 つ
6. `prefers-reduced-motion` では**距離を 0 にして変化は残す** (消さない)
7. **出現に opacity を主役にしない。** 初動で内容が霞み、読み始めが遅れる。主は大きさ (0.975 → 1.0)、従が向き (±6px)

## hover / focus

- **channel を分ける: hover は「地」、選択は「枠」。** 同じ channel を使うと「触れている」と「選ばれている」が混ざる
- 線のボタンのみ、地に加えて縁も一段起こす (押せる面であることを縁が担っているため)
- タッチでは hover を無効化 (`@media (hover: none)`)。指では hover がタップ後に残り、選ばれて見える
- キーボードでめくる導線がある以上 `:focus-visible` は必須 (`--border-strong` 2px / offset 2px)

## 尺度

- **文字は rem、レイアウトは px。** rem の基準は `html { font-size: 16px }` (WQHD で小さすぎたため 14 → 16)
- 文字は 7 段 (12 / 13 / 14 / 16 / 18 / 22 / 26px 相当) を `lib/idd-ui/scale.ts` の `FS` に持つ
- 判断面の幅は 1040px で中央寄せ。広い画面でも行長を伸ばさない
- 余白の階段は wireframe のまま (群の中 4-8 / 情報ブロック間 12 / 情報 → 操作 24 / 別の面 48)

## UI が要求した schema の追加

いずれも planner / 重複判定の出力に影響する。**設計側で確定が要る。**

| 追加 | 場所 | 理由 |
| --- | --- | --- |
| `shared: string[]` | 重複確認 | 「なぜ近いか」を文章で読ませない。両者に共通して現れた**具体物** (ファイル名 / 記号 / area) を列で出す。従来の `reason` (自由文) は ⓘ の tip に退避 |
| `existing.stage: { done, current }` | 重複確認 | 既存側が実在して進んでいることを stage bar で示す。ledger から取れる |
| DEC / QA の**見出しそのもの** | GO 待ち | `dec_count` ではなく本文の見出しを出す (open-questions 16 の方針を実装済み。`/^#{2,3}\s*((?:DEC|QA|INV)-[\w.]+)\s*[—–:-]?\s*(.+?)$/` で parse)
