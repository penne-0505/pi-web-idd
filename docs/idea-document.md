# アイデア文書の約束

アイデア文書は、アイデアを詰める会話が 1 つの Markdown ファイルに書く記録である。engine はこの約束に従って文書を読み、節ごとの状況・未決・段階・ゲートの記録・出口を返す。engine は約束が定める欄だけを読み書きする。

この約束は `docs/idea-template.example.md` にそのまま現れている。節の名前は既存のテンプレのままである。

## frontmatter

frontmatter は節の印と、置き場の宣言を持つ。

```yaml
---
slug: voice-attach
status: 探索中
target: github.com/penne-0505/pi-web
created_at: 2026-10-05
frozen_at:
sections:
  経緯: 決まった
  既存の確認: 詰めている
  目的: 決まった
  ゴール: 決まった
  非ゴール: まだ
  想定作業内容サマリ: まだ
  未決: 詰めている
  ゲート記録: まだ
  出口: まだ
places:
  - ~/text/ideas/out
---
```

- `slug` は文書の名である。
- `status` は段階を人が読むために写した値である。engine が書く。段階そのものは下の決まりで本文から導く。
- `target` は成果物の宛先である。
- `created_at` は文書を作った日である。
- `frozen_at` はゲート 2 の承認で engine が入れる日である。
- `sections` は節の印の表である。engine は印を書かない。
- `places` は出口が手元を変えてよい置き場の宣言である。home そのものとその祖先は受け付けない。
- `exit` の欄は持たない。出口は本文の「出口」の節に書く。

## 節の印

節の印は「まだ」「詰めている」「決まった」の 3 つである。印を書くのは agent である。

印の無い節は、本文が空なら「まだ」、本文に中身があれば「詰めている」と読む。「凍結」は印に書かない。凍結はゲート 2 の記録から決める。

## 未決

未決の件数は、`## 未決` の節の先頭の階層の箇条書きを 1 件ずつ数える。入れ子の箇条書きは数えない。

## ゲートの記録

ゲートの記録は `## ゲート記録` の節に 1 行 1 件で書く。行はゲートの番号・日付・承認かやり直しかを持つ。やり直しの行は理由を持つ。ゲート 2 の承認の行は指紋を持つ。

engine が書く行の形は次の 3 つに決める。

```
- ゲート 1: 2026-10-05 承認
- ゲート 1: 2026-10-05 やり直し — 目的が変わった
- ゲート 2: 2026-10-05 承認 指紋 <ハッシュ>
```

読み取りはこの形と、既存の文書の並び（`ゲート 1 (2026-10-05): 承認`、`ゲート 1: 2026-09-25 承認`、`ゲート 1（やり直し）: 2026-09-25 理由`）の両方を受ける。

## 段階

段階は、ゲートごとの最後の行から導く。

- ゲート 1 の承認が無ければ「探索」である。
- ゲート 1 の最後の行がやり直しなら、後ろのゲート 2 の承認も無効である。
- ゲート 2 の承認があれば「凍結」である。
- 凍結していて、出口の行が 1 つ以上あり、すべて実行済みなら「出口」である。

## 凍結と指紋

ゲート 2 の承認は、その時点の 4 点（目的・ゴール・非ゴール・想定作業内容サマリ）の本文のハッシュを指紋として行に書く。

状況の口は、今の 4 点のハッシュが行の指紋と違うとき、凍結が崩れていると返す。指紋の無いゲート 2 の承認の行だけを持つ文書も、凍結を確かめられないものとして扱う。凍結を確かめられない間は、出口の承認と実行を断る。

ゲート 2 をやり直すと、新しい指紋の行が足される。

## 出口の行

出口の行は `## 出口` の節に `###` の見出しで 1 行ずつ書く。見出しは行の id と 1 行の「何を」を持つ。

行は次の欄をこの順に持つ。本文の値は 4 つ以上のバッククォートで囲む。

`````text
### EXIT-1: 依存の記法を直す

- 効果: 外へ出る
- 操作: issues
- どこに: penne-0505/pi-web
- 戻し方: 戻せない
- 状態: 下書き
- 結果:
`````

- 効果は「外へ出る」か「手元を変える」である。効果は操作から決まる。申告した効果が操作と違う行は読めない行として扱う。
- 操作は `issues`・`repo`・`file` の 3 つである。
- どこに は Issue なら `owner/name`、repo なら `owner/name`、file ならパスである。
- 戻し方 は戻す手順である。戻せないときは `戻せない` と書く。
- 状態は「下書き」「承認済み」「実行済み」「失敗」の 4 つである。状態を書くのは engine である。
- 結果は実行の結果である。状態を書くのは engine である。

`状態` と `結果` は署名の中身に入れない。署名は行の中身（id・効果・操作・どこに・何を・戻し方）に掛かる。

## 操作の中身

### issues

Issue ごとに `####` の見出しを書き、その下に欄を書く。

`````text
#### EXIT-1-1: 依存の記法を直す

- 依存: []
- ラベル: [follow-up]
- 結果:
- 本文:
````text
本文
````
`````

- 見出しは Issue の id と題を持つ。
- 依存は同じ行の前の Issue の id を並べる。
- 本文は依存先を指す `{{EXIT-1-1}}` の記法を含められる。記法が指せるのは依存に挙げた Issue だけである。
- 外へ出すときは記法だけを依存先の番号に替える。本文のほかの文面は変えない。
- Issue の結果には番号と URL を書く。engine は Issue を 1 件作るたびに結果を文書に書く。作成済みの Issue はやり直しで作り直さない。

### repo

`````text
- 公開: public
- 説明:
````text
1 行の説明
````
`````

- 公開は `public` か `private` である。
- 説明は 1 行である。

### file

作成と追記は `本文` を持つ。置換は `前` と `後` を持つ。

`````text
- 変更: 作成
- 本文:
````text
足す文面
````
`````

`````text
- 変更: 置換
- 前:
````text
前の文面
````
- 後:
````text
後の文面
````
`````

- 作成は、既にファイルがあれば失敗する。
- 追記は末尾に足す。
- 置換は、前の文面がファイルのちょうど 1 か所に当たるときだけ替える。
- 全文の上書きと削除は受けない。

## 置き場の宣言

`places` に書いた置き場と、会話の workspace の中だけが、手元を変える出口の書ける場所である。パスはリンクを解決してから比べる。engine の state の置き場、propter の設定の置き場、アイデア文書そのものへの書き込みは、宣言と署名があっても断る。

## 途切れた行

副作用の後に結果を書く前に engine が止まると、行は「承認済み」で残る。状況の口はこれを「実行が途切れた」と返す。engine はこの行を、署名があっても実行し直さない。直すのは会話の中の agent か人である。宛先を確かめ、作られていたならその結果を行に書き、状態を「下書き」に戻す。それから新しい署名で実行する。
