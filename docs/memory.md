# 記憶の階層の約束

記憶は、会話の外に置く小さな Markdown の木である。会話を開き直しても、別の harness（pi CLI・Claude Code）で同じ workspace を開いても、同じ記憶に当たる。正本は workspace のファイルで、engine も propter もその写しを持たない。

engine は、会話の harness（pi と Claude Code）を起こすたびに、記憶の dir の所在と最上位の索引を system prompt への追記で渡す。どちらの harness にも同じ組み立ての同じ文面が渡り、索引はファイルの path として渡るので engine は中身の写しを持たない。会話を開き直したときも、そのときの索引が渡る。それ以外の本文は起動時に注入しない。agent は、索引の 1 行から領域の索引へ、領域の索引から件へと、要る記憶だけを辿って読む。

規範の正はこの文書である。engine はこの本文を持たない。workspace の `AGENTS.md` には、下の「AGENTS.md に貼る節」を写して使う。

## 置き方

記憶は 2 段に置く。

```
memory/
  MEMORY.md            最上位の索引。領域ごとに 1 行
  <領域>/
    MEMORY.md          その領域の索引。件ごとに 1 行
    <件>.md            1 事実 1 ファイル
```

- 全体の記憶の dir は、mode が決める（既定は workspace の `memory/`）。
- 領域は、自分の索引 `MEMORY.md` を持つ dir である。最上位の `MEMORY.md` は領域ごとに 1 行を持ち、その行は領域の索引を指す。
- 件は、領域の dir に置く Markdown ファイル 1 つである。1 つのファイルに 1 つの事実を書く。
- 領域の索引は、件ごとに 1 行を持ち、その行は件のファイルを指す。
- 件の本文は索引に書かない。索引に書くのは、題名と、その件を読むべきかどうかが分かるだけの要点である。

## 最上位の索引

最上位の `MEMORY.md` は、記憶の入口である。1 行は 1 つの領域を指す。

```md
- [暮らし](kurashi/MEMORY.md) 生活の手順と好み
- [道具](dougu/MEMORY.md) 使っている道具と設定
```

会話の agent は、このファイルを最初に読む。engine が起動時に追記で渡すのは、この索引の中身と、記憶の dir の所在と、このファイルの path だけである。

## 領域の索引

領域の `MEMORY.md` は、その領域の件への入口である。1 行は 1 つの件を指す。

```md
- [確定申告の手順](kakutei-shinkoku.md) 毎年 2 月にやる。使う道具と順番
- [自転車の空気圧](jitensha.md) 週 1 で見る。前 4.0 / 後 4.5 bar
```

## 件

件は `memory/<領域>/<件>.md` に置く 1 ファイルである。本文は事実を 1 つ書く。frontmatter は要らない。書いたら、領域の索引にその件の 1 行を足す。

新しい領域を作ったら、最上位の索引にもその領域の 1 行を足す。

## スペースの記憶

スペースの定義は workspace の `spaces/<id>/space.md` にある。その frontmatter の `memory:` が、スペースの記憶の扱いを決める。値は 3 つである。

- `none`: スペースの記憶を持たない（既定）。
- `space`: 記憶を `spaces/<id>/memory/` にだけ置く。形は領域と同じで、索引の `MEMORY.md` と 1 事実 1 ファイルを持つ。最上位の索引には足さない。
- `shared`: 記憶の本文を `spaces/<id>/memory/` に置き、最上位の索引 `memory/MEMORY.md` に、`spaces/<id>/memory/MEMORY.md` を指す領域の 1 行を足す。本文は 1 か所のままで、スペースの外の会話からも最上位の索引を通って辿れる。

扱いと置き場は、スペースに属する会話の pi に起動時の追記で伝わる。engine は記憶の dir もファイルも作らない。記憶の読み書きは agent が行う。

改名の前に作った定義（`projects/<id>/project.md`）は、更新するまで旧い `projects/<id>/memory/` が置き場として案内される。更新すると、定義と記憶が `spaces/<id>/` へ移り、次に pi を起こしたときから案内も `spaces/<id>/memory/` になる。

## AGENTS.md に貼る節

workspace の `AGENTS.md` に、下の節を写す。engine が索引を渡さない harness（pi CLI・Claude Code）でも、会話の agent はこれで最上位の索引を最初に読む。

````md
## 記憶

会話の最初に `memory/MEMORY.md` を読む。これは記憶の最上位の索引で、領域ごとに 1 行を持つ。聞かれた事柄に要る記憶は、その行から領域の索引を辿り、領域の索引から件のファイルを辿って読む。索引の 1 行だけで足りるなら、件の本文は読まない。

記憶を保存したら、置き場と索引を同じ手で直す。

- 記憶は `memory/<領域>/<件>.md` に、1 事実 1 ファイルで書く。
- 各領域の dir は自分の索引 `MEMORY.md` を持ち、件ごとに 1 行を持つ。
- 最上位の `memory/MEMORY.md` は領域ごとに 1 行を持ち、その行は領域の索引を指す。
- 件の本文は索引に書かない。
- 新しい領域を作ったら、最上位の索引にも 1 行を足す。
````
