# 文章の作法

人が読む文章を書くときの作法。正本はこのファイルで、planner / executor の brief にある inline は要点の写し。

## 対象

人間向けに書く文章すべて:

- DEC / AC / INV 見出し
- 質問の選択肢 label
- commit message
- PR 本文
- README や docs の文章

## 原則

1. **1 主張 1 文**。読点で節を継ぎ足さない。1 文に 2 つ以上の主張を入れない。
2. **判断に効かない修飾を落とす**。経緯、実装の関数名、括弧書きは、判断を変えない限り本文から落とす。
3. **出典や経緯は見出しに混ぜない**。「(質問 q1 の回答)」「(DEC-665)」のような括弧書きは見出しに入れず、Why や本文に書く。
4. **card に出る文字列は 1 行に収める**。DEC / AC / INV 見出しと質問の選択肢 label は UI の card にそのまま出る。目安は 40 文字前後。

## 長さの物差し

- **card に出る文字列** (DEC / AC / INV 見出し、質問の選択肢 label): 40 文字前後で 1 行に収める。折り返すと判断面の行が崩れる。
- **それ以外の文章** (commit message、PR 本文、README、docs): 1 主張 1 文を守れば長さは自由。

## 例

悪い例:

- `未達は Inbox 見出し行に総数、lane detail 見出しに lane 分を出す` — 読点で節を継いでいる
- `未達のうち error 付き (配送失敗) があるとき、総数とは別に失敗分であることが表示から読み取れる (DEC-665)` — 長く、括弧で出典を付けている

良い例:

- `未達は Inbox と lane detail の見出しに出す`
- `error 付きの未達は表示で失敗と区別できる`
