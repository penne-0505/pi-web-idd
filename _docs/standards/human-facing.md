# 人に届く card の文の型

受信箱の card は、判断する人 1 人が、記録の内部の語を読み解かずに上から順に読んで判断できる形で書く。
本書は、この repo の code が今守っている型・訳す役の契約・検査・人に回す基準だけを定める。code が守っていないことは載せない。

## 範囲

欄の組は 1 つで、card の種類によって変わらない。今、欄が埋まるのは GO の card だけである。ほかの種類の card は
欄を持たず、これまでの見え方のままである。種類を足すときは、欄の組を作り足さず、その種類の材料を足す。

## 文の型

6 欄を、この順に持つ。どの欄も空にならない。

| 欄 | 書くこと |
| --- | --- |
| 決めること | 問いの形で 1 文。 |
| 推奨と理由 | どれを推すか（選択肢の名前）と、理由として根拠にした材料の文（最大 2 件）。訳す役は文を書かず、選択肢の番号と材料の名前を選ぶだけで、理由の文は材料の文がそのまま出る。根拠が記録なら「記録」、自己申告だけか根拠を挙げなければ「推測」と添える（engine が決める）。推奨を作れないときは、推測とし、確かめていないと書く。 |
| 選ぶと何が起きるか | 選択肢ごとに、何が変わるか。誰（何）に及ぶかと、後から戻せるかは engine が選択肢ごとに決めた語を添える。 |
| 判断に要る事実 | 3 件まで。それぞれに出典を付ける。文は材料の文で、訳す役は書かない（材料を選ぶだけ）。 |
| もう決まっていること | card が生まれた時点で engine が既に決めていて、判断しなくてよいこと。まだ起きていない判断は載せない。文は材料の文で、訳す役は書かない（材料を選ぶだけ）。 |
| 詳しく見る場所 | リンクだけ。 |

書き方は、訳す役への指示として次を守らせる。

- 読み手は判断する人 1 人。前提を知らない日に読んでも分かる文にする。結論を先に書く。
- 内部の番号（DEC・C-・AC・P- など）は、中身の短い説明と一緒にだけ書く。
- 内部の語は言い換える。事実と推測を分け、確かめていないことは「確かめていない」と書く。

## 材料

訳す役には、その card の材料だけを渡す。ほかの lane や ほかの card は渡さない。材料の 1 つ 1 つは名前を持ち、次の印を持つ。

- 記録: lifecycle の出来事・差分・検査の結果・査読の判定・engine 自身の決めごと。
- 自己申告: エージェントが自分の仕事について書いた文（計画役の要約・計画役が書いた契約・Risk の表、実装役の報告）。
- 決まったこと: card が生まれた時点で engine が既に決めていたもの（自動 GO にしなかった理由・計画の査読の結果・同じ GO で確かめる Purpose の案・この lane の深さ・仕組みが代わりに答えた計画役の質問）。

GO の card の材料は、これらに加えて、依頼の題と、選択肢（GO と計画を直させる）ごとの、engine が決める起きることと及ぶ範囲と戻せるかである。
提出の検査と、後の巡で決まる指摘の扱いは、GO の時点で起きていないので材料に無い。

記録の事実を先に置く。自己申告を材料にした欄は、記録から組んだ欄と同じ顔では並べない。画面は自己申告の印を付けて出す。
印は、欄が引いた材料の印から engine が決める。訳す役は付けも外しもしない。

## 訳す役

role は `config/roles.yaml` の `card-writer`。対外文書の清書の役とは別で、model・thinking・`budget_minutes` を
それとは別に替えられる。道具・skill・拡張・規範文書・session は持たず、渡された材料の外を読まない。

- いつ書くか: card が初めて受信箱に出たとき、state の導出とは別に 1 発生成で走る。導出は記録を読むだけで、訳す役の応答を待たない。
- どこに残すか: state の `card-text/` に、card の同一性（`snoozeKey`）ごとに 1 ファイル。材料の fingerprint・書いた時刻・訳したか生か（`by`）・model・生のときの理由（`reason`）・6 欄の本体を持つ。
- 書き直し: 材料の fingerprint が同じ間は書き直さない。材料が変われば書き直す。外れた出力や失敗の記録も、同じ材料では書き直さない。
- 同時に走る数: 2。
- 費用: `conversation-cost.jsonl` に `mode: card-text` で role ごとに残す。lane の予算には数えない。
- role が無い設定: 訳す役を起こさず、すべての card を生の欄で出す。

## 検査

訳す役の出力は、決定論の検査を通ったものだけが card に出る。1 つでも外れれば、その card には訳す役の文が 1 つも出ず、
生の材料から組んだ 6 欄が出る。外れた理由は card の記録の `reason` に残る。検査は次の通りである。

- JSON の object で、決めることが問い（？で終わる）で、書く文が上限の文字数（決めること 120・選択肢ごとの何が変わるか 160）を超えない。この上限は訳す役への指示にも同じ値で書く。上限を超えた文が 1 つあれば、6 欄すべてが生の欄に戻る。
- 推奨は、選択肢の番号（1〜選択肢の数）か、作れないときの `null` と、出典（材料の名前、最大 2 件、同じ材料は 2 度選べない）だけを持つ。範囲外の番号・数でない番号・材料に無い名前は外れる。
- 推奨の文は、選択肢の名前と、出典の材料の文から engine が組む（記録の材料はその文のまま、自己申告の材料は先頭の 1 行）。出典を挙げない番号は「根拠にした材料を挙げていない推測で、確かめていない」と engine の定型文で出す。`null` は生の欄と同じ推奨である。訳す役が理由の文や根拠の種別を添えても読まず、捨てる。
- 推奨の根拠の種別は engine が決める。出典に記録の材料があれば記録、自己申告の材料だけか出典が無ければ推測である。
- 推奨は、出典が無いときと、出典が自己申告の材料を含むときに、engine が自己申告の印を付けて出す。印を決めるのは出典の有無と材料の種類で、訳す役の申告ではない。
- 判断に要る事実は 1〜3 件で、渡した材料の名前を選ぶ。同じ材料は 2 度選べない。
- もう決まっていることは、「決まったこと」の印の材料の名前だけを選び、同じ材料を 2 度選ばず、その材料を 1 つも省かない。
- 事実・もう決まっていること・推奨の理由に、訳す役の文は無い。表示する文は engine が選ばれた材料から引く。訳す役が文を添えても読まず、捨てる。そのため、材料に無い事実や、材料と食い違う事実は、この 3 欄に構造上入らない。
- 内部の番号は、材料が持つ番号と完全に一致するものに限り（`DEC-1` は材料が `DEC-12` しか持たなければ通らない）、番号だけで中身を表さない。この検査は、訳す役が文を書く 2 欄（決めること・選ぶと何が起きるか）にかける。
- 訳す役が書く 2 欄の文は、根拠にした文に支えられる。文中の数は、根拠の文に同じ数字の連なりとして在る。評価の語（must・should・nit・浅い・標準・深い・失敗・走らなかった・通す理由・差し戻）は、根拠の文にも在る。根拠の文は、選ぶと何が起きるかでは engine が決めた選択肢の語、決めることでは問いである。
- 選択肢と同じ数の「何が変わるか」を持つ。

数と評価の語の検査は、材料と食い違う数や判定を止めるだけである。同じ数と語を使って主張を逆にした文は検出できない。この限界が当たるのは、訳す役が文を書く決めることと選ぶと何が起きるかだけで、事実・もう決まっていること・推奨の理由は文を書かせないので限界の外にある。
推奨の番号が妥当か（その選択肢を推すこと自体）は検査できない。理由は材料の文のまま並ぶので、誤った推奨は材料と食い違って見える。

訳す役が失敗したとき（起動できない・時間切れ・空の応答）も、同じ生の欄で出し、理由を記録に残す。

## 査読の経緯

計画の査読の材料にある経緯は、台帳に記録された出来事だけから組む。巡の数から差し戻しを推測しない。

- 巡: lane の頭からの `s1_plan_review_done` と `s1_plan_review_skipped` を古い順に並べる。penne が計画の出し直しを指示する前の巡も含む。
- 差し戻し: 巡の記録が `sent_back` を真偽で持つときだけ、「計画役に差し戻した」「差し戻さなかった」と書く。記録が無い巡、失敗した巡、走らなかった巡は、差し戻しについて何も言わない。
- penne の指示: `s1_revise_requested` を「penne が計画の出し直しを指示した」と 1 行で書く。
- 記録に差し戻しが 1 件も無いときも「差し戻しは無い」とは書かない。書くのは記録にある事実だけである。

## 生の欄

生の欄は、model を呼ばずに、材料から決まった形で組む。推奨は「記録だけからは作れない」と書く。
判断に要る事実は、記録の材料を先に、自己申告の材料を後に、3 件まで。もう決まっていることは「決まったこと」の材料だけで、各材料は全行を 1 行 1 件で載せる（先頭行で切らない）。

## 人に回す基準

判断の性質は、何が変わるか・誰に及ぶか・戻せるかの 3 つで読む。及ぶ範囲が広いもの、戻せないものほど人に回す。

人に回すもの（既定）:

- 範囲を広げる・狭める（依頼の決めと違う形を選ぶ）。
- 優先度・順番。
- 利用者や外の人から見える挙動を変える。
- 取り返しのつかないもの（資格・データ・外への書き込み・稼働の形・ファイルを動かす処理）。
- 既存の決め（記録された決定）と逆向きの判断。
- 署名。

人に回さないもの（仕組みが決め、決めたことを card に載せる）:

- 計画役の質問のうち、既存の Choice・Issue の本文・`_docs/standards/` の規範を引けば答えが決まるもの。次の節がこの実装の契約である。

権限の線は持たない。責任を負う人がどこまで裁量を持つかは人・チーム・時期で違い、propter は追いきれない。見るのは判断の性質だけで、「人に回すもの」に当たれば人に回す。
利用者の方針（自然文）を読んで、人に回すものを仕組みの答えに緩める部分はない。

## 仕組みが答える計画役の質問

対象は計画役の質問だけで、GO の前の質問に限る。計画の段の答えは GO の card を通るので、仕組みが誤って答えても人が GO の前に見て直せる。実装の段（GO の後）の質問は人に回す。

この節の基準が働くのは、`config/roles.yaml` の `pipeline.question_routing` に判定役の role を書いたときだけである。キーを省いた環境では判定役を起こさず、質問は全部人に回る。この節の「人に回さないもの」は、その環境では何も代わりに答えない。

役割は、判定役と engine で分ける。

- 判定役（`config/roles.yaml` の `question-router`）が、質問ごとに、人が決めるか記録で決まるかと、その種類（上の 6 つか、記録で決まる `settled`）と、選ぶ選択肢の番号と、引用を決める。迷うときは人に回す。道具は読むだけで、worktree の外は読めない。
- engine は言葉を読まない。質問の文に語の一覧を当てて種類を決めることはしない。確かめるのは次だけである。種類が `settled` で、選択肢の番号が質問のものにあり、引用が材料の中に実在すること。
- 引用の実在は、engine が材料として渡した 1 つの Choice の 1 つの欄（chosen・why・anchored・free）、Issue の本文、`_docs/standards/` の規範のファイルのどれかに、連続した文字列として在ることである。空白は畳んで比べる。材料に無い Choice、2 つの欄をつないだ引用、`_docs/standards/` の外のファイル、短すぎる引用は根拠にならず、その質問は人に回る。
- 引用が選んだ答えを支えているかは、engine は確かめられない。この限界の受け皿は、答えを GO の card の「もう決まっていること」に質問・答え・引いた記録・引いた文として並べ、人が GO の前に見て直せることである。
- 判定役が動かないとき（設定のキーが無い・起動できない・時間切れ・出力が形を外れた）は、その batch の質問は全部人に回る。人が先に答えた質問の答えは置き換えない。
- 判定役は質問を受けたその場で起こし、結果が出るまで質問を card にも lifecycle にも出さない。この間は、人の GO も自動 GO も通らない。結果を書く前に engine が止まったときは、次の tick で、判定役が答えなかった batch として全問を人に回す書き方で書き戻す。
- 材料には、質問が path を持たなくても、その lane に適用できる active な root の Choice が入る。root の Choice が 1 つでも材料に収まらない batch は人に回る。
- 仕組みだけが答えた batch は、人の「今日答えた」件数と進みの数に入れない。人が 1 問でも答えた batch は入れる。

仕組みが答えた質問は、答えの記録（`pending-answers.jsonl`）の行に、答えた者（`answered_by`・`router`）と根拠（`basis`）を持つ。人の答えの行は持たない。
